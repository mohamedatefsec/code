# Code AI — Phase 1 → 8 (المشروع الكامل) + السؤال المقالي

منصة تعليمية لتدريس البرمجة والذكاء الاصطناعي لطلاب المرحلة الثانوية.

## Phase 1 (Foundation) ✅
مصادقة كاملة، حماية أدوار عبر `proxy.ts`، صفحة Settings ديناميكية.

## Phase 2 (Students & Groups) ✅
إدارة كاملة للطلاب والمجموعات من لوحة الأدمن فقط.

## Phase 3 (Educational Content) ✅
مواد / وحدات / دروس / وسائط.

## Phase 4 (Question Bank) ✅
بنك أسئلة بخمسة أنواع + السؤال المقالي (essay) — إضافة لاحقة، تفاصيلها تحت.

## Phase 5 (Exams) ✅
بناء اختبار، استهداف، تصحيح تلقائي، نتائج تفصيلية.

## Phase 6 (Attendance) ✅
مجموعة → تاريخ → حصة، حساب نسبة الحضور تلقائيًا.

## Phase 7 (Notifications & Gamification) ✅
إشعارات مستهدفة، شارات تُمنح تلقائيًا حسب الإنجاز.

## Phase 8 (AI Question Generator) ✅
- صفحة `/admin/ai-generator`: اختر مادة، وحدة (اختياري)، موضوع نصي، أنواع
  الأسئلة، العدد، ومستوى الصعوبة
- **تدفق إلزامي بلا استثناء: Generate → Review → Edit → Approve → Publish**
  — لا يوجد أي مسار ينشر سؤالًا تلقائيًا. كل سؤال يُولَّد يُحفظ **دائمًا
  كمسودة (`draft`)**، ويحتاج الأدمن يراجعه ويعدّله (بنفس فورم إنشاء الأسئلة
  العادي تمامًا) ثم يحفظه، وبعدها ينشره يدويًا من بنك الأسئلة كالمعتاد
- تحقق تلقائي من قواعد كل نوع سؤال (زي بنك الأسئلة العادي بالظبط) قبل عرضه
  للمراجعة — أي سؤال ما يلتزمش بالقواعد يُستبعد بهدوء بدل ما يُفشل الطلب كله

## السؤال المقالي (Essay) — إضافة بعد Phase 8 ✅

نوع سؤال سادس مختلف جوهريًا عن الخمسة السابقين: **بلا تصحيح آلي إطلاقًا**.
الطالب يكتب إجابة حرة، والمدرّس يقرأها ويحط الدرجة بنفسه.

- **إنشاؤه**: من بنك الأسئلة أو مولّد الذكاء الاصطناعي، زي أي نوع تاني —
  اختر "سؤال مقالي" ولن يُطلب منك أي خيارات، فقط نص السؤال والدرجة القصوى
- **أداء الطالب**: يظهر كمربع نصي حر بدل الاختيارات
- **بعد التسليم**: لو الاختبار فيه سؤال مقالي واحد على الأقل، الدرجة والنسبة
  التي يراها الطالب فورًا **جزئية** (من الأسئلة القابلة للتصحيح الآلي فقط)،
  مع رسالة واضحة "بانتظار تصحيح المدرّس"
- **التصحيح** (`/admin/grading` — تبويب "التصحيح اليدوي" جديد في القائمة
  الجانبية): قائمة بكل المحاولات المعلّقة، تفتح كل واحدة وتشوف إجابة الطالب
  كاملة، وتحط درجة لكل سؤال مقالي (من 0 لحد الدرجة القصوى للسؤال)، وتحفظ —
  الدرجة والنسبة النهائية تتحدّث فورًا، والشارات (زي "الطالب المتميز") تُقيَّم
  وقتها لأول مرة بدرجة نهائية حقيقية

### ⚠️ خطوة قاعدة بيانات مطلوبة لهذه الإضافة

## التشغيل محليًا

> ملاحظة: تم بناء هذا الكود داخل بيئة sandbox بلا اتصال إنترنت كامل، لذا لم
> يتمكن Prisma من تحميل ملفات المحرك (Engines) للتحقق من البناء هنا. هذا لن
> يحدث على جهازك أو على Vercel، لأن كليهما يملك اتصال إنترنت طبيعي.

1. **تثبيت الحزم**
   ```bash
   npm install
   ```

2. **إعداد متغيرات البيئة**
   ```bash
   cp .env.example .env
   ```
   ثم عدّل:
   - `DATABASE_URL` → رابط اتصال Postgres (من Neon أو Supabase أو أي مزود متوافق)
   - `JWT_SECRET` → قيمة عشوائية طويلة، يمكن توليدها بـ `openssl rand -base64 48`

3. **توليد Prisma Client ورفع الجداول لقاعدة البيانات**
   ```bash
   npx prisma generate
   npm run db:push
   ```

4. **إنشاء أول حساب أدمن (Seed)**
   ```bash
   npm run db:seed
   ```
   ينشئ حساب أدمن افتراضي: `admin@codeai.local` / `ChangeMe123!`
   (يمكن تخصيصهما بمتغيرات `SEED_ADMIN_EMAIL` و`SEED_ADMIN_PASSWORD` قبل التشغيل)

   ⚠️ **غيّر كلمة المرور فور أول تسجيل دخول** — لا توجد حاليًا صفحة لتغيير
   كلمة المرور من الواجهة (ستُضاف ضمن وحدة إدارة الطلاب/الحسابات في Phase 2)،
   فعدّلها مباشرة عبر `npx prisma studio` مؤقتًا إن احتجت.

5. **تشغيل المشروع**
   ```bash
   npm run dev
   ```
   ثم افتح `http://localhost:3000` — ستُحوَّل تلقائيًا لصفحة تسجيل الدخول.

## النشر على Vercel

1. ارفع المشروع إلى مستودع Git.
2. أنشئ قاعدة بيانات على Neon (تعمل بسلاسة مع Vercel + Prisma).
3. اربط المستودع بمشروع جديد على Vercel، وأضف نفس متغيرات البيئة
   (`DATABASE_URL`, `JWT_SECRET`) من إعدادات المشروع على Vercel.
4. أضف `"postinstall": "prisma generate"` في `package.json` إن لم يُنفَّذ تلقائيًا
   أثناء البناء على Vercel.
5. بعد أول نشر، شغّل `npx prisma db push` و`npm run db:seed` مرة واحدة (محليًا
   مع تعديل `DATABASE_URL` لتشير لقاعدة الإنتاج، أو عبر Vercel CLI).

## القرار المعماري (ملخّص)

Modular Monolith على Next.js: كل Domain (auth, students, content,
questions, quizzes, attendance, notifications, ai...) له طبقة منطق أعمال
مفصولة، بحيث يسهل استخراجه لاحقًا كخدمة مستقلة إن احتاج المشروع ذلك دون
إعادة بناء من الصفر.

## إضافة: رفع الصور مباشرة (بدل الرابط) + خط أكبر

استجابةً لملاحظاتك:

- **صورة المدرّس تُرفع كملف مباشرة** من جهازك من صفحة الإعدادات (زرار "رفع
  صورة") بدل الحاجة لرابط جاهز — مع معاينة فورية وزرار "إزالة"
- الصور المرفوعة تُحفظ في `public/uploads/` محليًا وتُخدَّم مباشرة
- **خط الصفحة الرئيسية العامة كُبِّر بالكامل**: العنوان الرئيسي، الوصف،
  الشارات الثلاث، عناوين الأقسام، وكل النصوص الأساسية — قراءة أوضح وحضور
  بصري أقوى

### ✅ رفع الصور يستخدم الآن Vercel Blob
`app/api/upload/route.ts` بيرفع الصور مباشرة إلى Vercel Blob (تخزين خارجي
دائم) بدل القرص المحلي، فبتفضل موجودة بعد أي نشر جديد على Vercel.

**خطوة مطلوبة مرة واحدة على Vercel:** من لوحة تحكم المشروع → **Storage** →
**Create Database** → اختر **Blob** → اربطه بالمشروع. Vercel بيضيف متغير
`BLOB_READ_WRITE_TOKEN` تلقائيًا، مفيش حاجة تانية تعملها.

للتطوير المحلي: `vercel env pull .env.local` بعد ربط المشروع بـ Vercel CLI
هيجيب نفس التوكن، أو أنشئ Blob Store مستقل من لوحة تحكم Vercel وحط التوكن
يدويًا في `.env`.


المنصة دلوقتي عندها واجهة عامة حقيقية قبل تسجيل الدخول (بدل التحويل المباشر
لصفحة الدخول)، بنفس روح التصميم العصري:

- **Hero بقسمين**: عنوان كبير + بطاقة المدرّس (بصورته لو ضفتها)، مع عناصر
  عائمة متحركة وخلفية متدرّجة خفيفة
- **إحصائيات حقيقية** (مش أرقام ثابتة يدويًا): عدد الطلاب المسجّلين، عدد
  الدروس المنشورة، عدد الاختبارات — كلها بتتحسب لحظيًا من قاعدة البيانات
- **قسم المسارات**: يعرض تلقائيًا كل مادة فيها محتوى منشور فعليًا (لو مفيش
  محتوى منشور، القسم بيختفي تلقائيًا بدل ما يبان فاضي)
- **قسم المميزات + قسم تواصل معنا** (بريد، هاتف، روابط تواصل اجتماعي) —
  يستخدم بيانات كانت موجودة في الإعدادات من زمان لكن مالهاش استخدام فعلي
  قبل كده
- **زرار الوضع الداكن** شغّال هنا كمان

### التحكم الكامل من لوحة الأدمن
صفحة **الإعدادات** (`/admin/settings`) اتقسّمت لـ3 أقسام واضحة:
1. **الهوية العامة**: اسم المنصة، اسم وصورة المدرّس، الوصف، الألوان
2. **الصفحة الرئيسية**: العنوان الكبير، الجملة المميزة تحته، و3 عبارات
   قصيرة (Badges) تظهر تحت المقدمة
3. **التواصل والروابط**: البريد، الهاتف، فيسبوك/إنستجرام/يوتيوب/واتساب،
   ونص الفوتر

فيه زرار **"👁️ معاينة الصفحة الرئيسية"** أعلى صفحة الإعدادات يفتحها في تبويب
جديد فورًا للتأكد من الشكل.

**لا حاجة لأي تعديل جديد في قاعدة البيانات** — الحقول دي (`heroHeadline`,
`heroBadges`) كانت أُضيفت بالفعل ضمن تحديث `db:push` السابق.


استجابةً لطلب تجديد الشكل، اتعمل تحديث بصري شامل لكل صفحات المنصة (أدمن
وطالب على السواء)، مش بس صفحة واحدة:

- **نظام ألوان جديد بالكامل** بنسختين (فاتح/داكن) مبني على متغيرات CSS،
  بلمسة "محرر أكواد" (الشريط الجانبي داكن ثابت في الوضعين، تدرّج إنديجو→
  بنفسجي→تركواز يمثّل "برمجة + ذكاء اصطناعي")
- **زرار تبديل الوضع الداكن/الفاتح** (🌙/☀️) في أعلى كل صفحة، يحفظ اختيارك
  محليًا، بدون أي "وميض" لوني لحظة تحميل الصفحة
- **حركة وانتقالات ناعمة** (framer-motion): الأرقام في الإحصائيات "بتعدّ"
  لأعلى بدل ما تظهر فجأة، البطاقات تدخل بتتابع لطيف، عنصر التنقّل النشط في
  القائمة بيتحرك بسلاسة بدل القفز، تأثير Glass (زجاج ضبابي) على الشريط
  العلوي الثابت
- **بطاقات وظلال أعمق** (`shadow-elevated`, `card-hover`) بدل الحدود
  المسطّحة البسيطة، مع تأثير ارتفاع خفيف عند الـ hover
- كل صفحات لوحتي الأدمن والطالب اتحدّثت بنفس النظام — مش تصميم جزئي

**لا حاجة لأي تعديل في قاعدة البيانات أو `.env`** لهذا التحديث — تعديلات
واجهة بحتة. فقط `npm install` عادي (بيضيف `framer-motion` كحزمة جديدة).


- بنك الأسئلة الآن فيه نوع سادس: **"سؤال مقالي"** — بدون خيارات إطلاقًا،
  الطالب يكتب إجابة حرة.
- **لا تصحيح آلي** لهذا النوع بطبيعته. بعد ما الطالب يسلّم اختبارًا فيه سؤال
  مقالي، تظهر المحاولة في قسم جديد **"التصحيح اليدوي"** (`/admin/grading`)
  في القائمة الجانبية.
- من هناك، تفتح كل محاولة وتشوف إجابة الطالب النصية، وتحط الدرجة بنفسك لكل
  سؤال مقالي (بحد أقصى درجة السؤال نفسه). بمجرد الحفظ، الدرجة والنسبة
  النهائية للمحاولة تتحدّث تلقائيًا، والشارات المرتبطة بالدرجة (زي "الطالب
  المتميز") تُقيَّم وقتها.
- لحد ما يُصحَّح السؤال المقالي، الطالب يشوف في صفحة نتيجته تنبيهًا إن
  الدرجة "جزئية" وبانتظار التصحيح.
- **لا تعديل على قاعدة البيانات مطلوب بتشغيل migration منفصل** — فقط
  `npm run db:push` عادي زي أي تحديث Schema سابق (بيضيف عمود
  `needs_manual_grading` الجديد فقط، لا جداول جديدة).
